# ARK website (aireadiness4kids.org)

This repo is being rebuilt from a marketing site into ARK's free course platform. The full spec is **`docs/ARK_UI_BUILD_BRIEF.md`**. Read it before starting any phase. The phase prompts are in `docs/ARK_Claude_Code_Prompts.md`.

## Current state
- `main` is the live site: React 18 + Vite + Tailwind v4 + shadcn/Radix (Figma Make export), with React Router.
- `platform-v1` (Phases 0 to 6 done; waiting for the team's review and the cutover in `DEPLOY.md`): Astro 7 + React islands + MDX + Tailwind v4, `output: 'server'` with the Netlify adapter. Pages without a session set `prerender = true`; lesson steps, `.../complete`, `/account`, `/my-learning`, `/certificates/*`, `/verify/*`, `/admin`, `/present/*`, `/forbidden`, and `/api/*` are server-rendered; `/check/[module]/[phase]` (open workshop checks) and `/educators/**` are static. A server page that needs the 404 page returns `new Response(null, { status: 404 })` (`Astro.rewrite("/404")` fails: the 404 page is prerendered).
- Course content lives in content collections (`src/content.config.ts`, zod-validated): `src/content/tracks/*.md` and `src/content/modules/<track>/<slug>/index.mdx` (17 stubs, all `status: draft`). `src/lib/courses.ts` loads and orders them. The three tracks are `aware` (AI Aware, K-5), `literate` (AI Literate, 6-8), and `fluent` (AI Fluent, 9-12). They were renamed in October 2026; the old ids appear only in `src/lib/renamed-tracks.mjs`, which drives the redirects from old URLs and maps old module ids in the guest key. `scripts/count-renamed-tracks.ts` (read-only) and `scripts/migrate-renamed-tracks.ts` (preview unless `--apply`) find and move Firestore data still under the old ids. Course pages are `src/pages/courses/`; their Astro components are in `src/components/`. Reviewer names come from module frontmatter; partner logos and impact numbers come from `src/data/*.json` (see `src/data/README.md`), and those home-page sections stay hidden while empty.
- Lesson steps are `NN-slug.mdx` files beside a module's `index.mdx` (steps collection); `guide.mdx` is the facilitator guide. The player is `src/pages/courses/[track]/[module]/[step].astro` with `src/components/lesson/LessonPlayer.astro`, using Astro View Transitions (`<ClientRouter />`) so the outline and the progress store (`src/app/lesson/progress.ts`) carry between steps. MDX lesson components are in `src/components/lesson/` (Astro wrappers) and `src/app/components/lesson/` (React islands); `<Check />`, `<Scenario />`, `<Sort />` read the step's frontmatter and `<Vocab />` the module's vocabulary via `Astro.locals.lesson`. Sample module: AI Literate > Bias in AI. `/dev/components#lesson` and `/dev/lesson-preview/1` (AI Aware variant) are noindex previews.
- Accounts (Phase 3, setup in `docs/SETUP_FIREBASE.md`): the browser signs in with the Firebase SDK (in-memory), `/api/session` swaps the ID token for the httpOnly `__session` cookie, and `src/middleware.ts` verifies it and gates routes (`src/lib/gate.ts`). API routes use `postRoute`/`getRoute` from `src/lib/api.ts` (POST + Origin check, App Check, zod) and `src/lib/authz.ts`; Firestore is only touched through `src/lib/firebase-admin.ts` and `src/lib/accounts.ts`. Security headers come from `src/lib/security/policy.mjs`: scripts are allowed by hash, so any new inline script must go in `src/lib/security/inline-scripts.mjs` (the build fails otherwise).
- Progress and data (Phase 4, brief sections 8.2 and 8.5 to 8.7): the browser's progress store is `src/app/lesson/progress.ts` (same API the islands always used; `completed.has(step.id)`). Signed in, it loads `/api/progress` and saves through `/api/progress/{step,precheck,merge}`; signed out, it keeps the guest key `ark.guest.v1` (`src/app/lesson/guest.ts`), merged into the active learner on the first signed-in page load and then cleared. Server side: `src/lib/learning.ts` (progress docs keyed by step slug, the `ark_learner` active-learner cookie), `src/lib/stats.ts` (running-total `stats/*` counters, written in the same transaction as the change), `src/lib/catalog.ts` (valid modules and steps, server-side scoring), `src/lib/checks.ts` + `src/pages/api/checks.ts` (open workshop checks, deduped per person, rate-limited by `src/lib/rate-limit.ts`). `?src=` is captured by `src/app/lib/src-capture.ts`. Analytics: `src/lib/analytics.ts` (Umami only when `PUBLIC_UMAMI_ID` is set). Islands that POST from many pages use `src/app/lib/post.ts`, which loads App Check with `import()` so pages don't ship the Firebase SDK until they save something.
- Completion, educators, presenter, admin (Phase 5, brief section 7): the last step's "Finish module" waits for its save (`progress.flush()`), then opens `/courses/<track>/<module>/complete` (post-check via `/api/progress/postcheck` with the before/after line, certificate via `/api/certificates/issue`, next module). Certificates are `src/lib/certificates.ts` (random 128-bit ids, one per learner and module via `progress.certificateId`; public only for a 13+ learner's own profile), shown at `/certificates/[id]` (owner only, prints on one landscape letter page) and `/verify/[id]` (public ones only: name, module, date). `/educators` and `/educators/[track]/[module]` render `guide.mdx` (portrait letter print styles; `src/styles/print.css` hides the site chrome and anything `data-no-print`). `/present` and `/present/[track]/[module]` (facilitator or admin) render every step as a slide with `src/components/present/present-components.tsx` (read-only versions of the interactive components) and server-drawn QR codes (`src/lib/qr.ts`, the `qrcode` package) that carry the presenter's `?src=`; presenter pages don't capture `?src=` themselves (`SiteHead captureSrc={false}`). `/admin` reads only `stats/*` through `src/lib/impact.ts` (filters `?source=&from=&to=`; `source`, not `src`, which would be captured), with the CSV at `/api/admin/stats.csv`. The stats docs' `bySrc_*` and `daily_*` now carry nested `byModule` maps for that.
- Organization pages (About, Workshops (was /programs), Get involved, Donate, Contact) use `src/app/components/site/Primitives.tsx` + `PageHero.tsx`. Privacy, terms, and accessibility are MDX pages with `src/layouts/DocLayout.astro` (`draft: true` shows the legal-review banner; `<ReviewNote>` marks questions for the lawyer). The parent notice text is `src/app/lib/legal.ts`, shared by sign-up and /privacy. Redirects (`/curriculum`, `/programs`, and every old course, educator guide, and presenter URL from the course rename) are in `astro.config.mjs`.
- Routes are `.astro` files in `src/pages/`; page sections in `src/app/sections/`; shared components in `src/app/components/site/` and shadcn primitives in `src/app/components/ui/`. Copy lives in `src/app/lib/content.ts`, tokens in `src/styles/theme.css`, brand assets in `public/brand/`. Style guide: `/dev/components` (noindex, unlinked).
- Islands and hydration (brief section 2): forms keep what people type before their island hydrates (`Field`/`SelectField`, or `useEarlyInput` from `src/app/components/ui/use-hydration.ts`), and submit buttons are `SubmitButton` (disabled until hydrated, so the browser never sends a form itself with the password in the URL). In tests, call `hydrated(page)` from `tests/support/hydration.ts` before typing; the `ssr` attribute goes before React commits. New form islands get a `beforeHydration()` test.
- Commands: `npm run dev` (port 5180), `npm run build` (production; also checks alt text, links, inline scripts vs the CSP, and bundle secrets), `npm run check:contrast`, `npm run check`. Tests run on the Firebase emulators (project `demo-ark`, never production) and need the Firebase CLI and Java 21+: `npm test`, `npm run test:security`, `npm run test:visual`, `npm run test:a11y`. `tests/print.spec.ts` writes the print views as PDFs (Playwright's `page.pdf`) to `screenshots/<phase>/`. `npm run build:test` + `npm run emulators` + `npm run preview` runs the site locally with sign-in.
- **Pushing to `main` deploys to production.** Until the cutover that's the old site on GitHub Pages (`deploy.yml` on `main`). `platform-v1` replaces it with `.github/workflows/ci.yml` (build + tests only, deploys nothing) and `netlify.toml`; after the cutover Netlify builds `main`. The step-by-step cutover and rollback are in `DEPLOY.md`.
- Domain and DNS: **Cloudflare** (stays there). Hosting target after cutover: **Netlify**. At cutover, only Cloudflare DNS records change.

## Rules
1. **Work on the `platform-v1` branch. Never push or merge to `main`** unless the user explicitly says to do the cutover.
2. Build one phase at a time (brief section 10). Stop and report after each phase.
3. **Soft gate:** catalog, course pages, module overviews, step 1 of every module, educator guides, and workshop checks are open. Everything else requires sign-in, checked on the server.
4. **Security** (brief section 8):
   - Use Firebase Auth with httpOnly session cookies.
   - The browser never talks to Firestore directly; its rules deny all client access.
   - Every server route checks ownership through `src/lib/authz.ts`.
   - Never commit or print the Firebase service account key.
5. **Kids' data:**
   - Under-13 learners are nickname-only profiles under a parent account.
   - Store the age band, never a birth date.
   - Reflections stay in the browser.
6. **Accessibility:** WCAG 2.2 AA; axe finds no serious or critical issues; everything works by keyboard.
7. **Content:**
   - Never invent statistics, studies, or quotes. Use `[CITATION NEEDED]`.
   - New modules start as `status: draft`.
8. **Dependencies:** use Tailwind and the existing `src/app/components/ui` primitives before adding any UI library, and explain any new dependency. Keep the `overrides` pin of `jose` 5 under `jwks-rsa` in `package.json`: firebase-admin 14 pulls in `jose` 6, which is ES-module-only, and Netlify's function runtime can't `require()` it, so every server route crashes with `ERR_REQUIRE_ESM`. Check before removing it with `node --no-experimental-require-module` against the built `.netlify/v1/functions/ssr/ssr.mjs`.
9. **After each phase:**
   - Run the build, visual screenshots (375/768/1280), and a11y tests.
   - Look at the screenshots and fix problems.
   - Commit, then report.
